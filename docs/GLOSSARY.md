# Glossary

Four systems in this ecosystem share overlapping vocabulary. This page fixes the terms so "v3" and "SkillStore" are never ambiguous again.

## The four

**Skill Core** — *This repository.* A filesystem-as-state store and workflow compiler. Holds exact, pinned upstream SKILL.md files; composes them via declarative `workflow.toml` manifests; projects them into `.agents/skills/` for Codex, OpenCode, and GitHub agents. Records run state as files under `runs/`. Formerly titled "SkillStore v3" in early documents (PRD/TDD dated 2026-08-04). **Not a runtime.** It does not execute skills; hosts do.

**SkillStore v1.x** — *Archived, superseded.* A Python package (v1.0.0 → v1.4.0, 2025-10 → 2026-03) implementing a 3-tier Primitive/Functional/Module hierarchy over SQLite, with a Voyager learning loop, refiner, and token-economics tracker. **Shares no code and no concepts with Skill Core beyond the word "skill."** v3 is not v1.4 + 2. See `decisions/0003-skillstore-v1x-archived.md`.

**Filesystem-As-State** — *Design rationale, not a system.* The body of reasoning behind Skill Core's structure: folders as routing, files as knowledge, no database, no orchestration framework. Relocated to `docs/WHY_FILESYSTEM_AS_STATE.md`.

**Process Discovery Engine (PDE)** — *Folded in, not standalone.* A 2026-08-08 specification for converting narrated process recordings into automation artifacts sorted by execution type. Its one novel contribution — the sorting decision — became `workflows/process-discovery/`. Its pipeline, gating, and state-tracking duplicated Skill Core and were dropped. See `decisions/0002-process-discovery-as-workflow.md`.

## Terms

**APA** *(from PDE)* — Agentic Process Automation. Work requiring language reasoning over variable input. Emits a candidate skill.

**Approval gate** — A workflow stage that halts until a human approves. Declared in `workflow.toml`; pauses the run, leaving state on disk.

**HITL** *(from PDE)* — Human-in-the-Loop. Work whose consequences are irreversible or high-risk. Emits a gate, never an automation.

**Lock** — `skill-core/sources.lock.json`. Records commit SHA, blob SHA, sha256 content hash, and license for every vendored skill. Generated by `scripts/lock_sources.py`; never hand-edited.

**Projection** — The generated `.agents/skills/` tree. Owned by the installer via `.skillstore-projection.json`. The installer touches only paths it declares; unmanaged user skills survive refresh.

**RPA** *(from PDE)* — Robotic Process Automation. Fixed-schema, zero-judgment work. Emits a script, not a skill.

**Run** — One execution of a workflow. Durable, resumable, stored at `runs/<run-id>/`. Chat sessions are transport; the run directory is state.

**Selection** — `skill-core/selection.json`. The curated list of skill IDs and their source repositories. A human decision; never auto-edited by tooling.

**Vendoring** — Copying an exact upstream skill into `skill-core/vendor/<source>/<id>/` without modification. Requires a permissive license.

**VSA** — Vertical Slice Architecture. Organizing by feature boundary rather than technical layer. Also used for release milestones (VSA 0.1, 0.2, …).
